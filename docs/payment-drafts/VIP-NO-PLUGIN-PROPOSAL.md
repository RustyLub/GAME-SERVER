# VIP Queue Pass без плагинов — техническое предложение

> **СТАТУС: ТОЛЬКО ПРЕДЛОЖЕНИЕ. НЕ РЕАЛИЗОВАНО.**  
> Rusty.Lub EU Long остаётся строго Vanilla. На сервер не устанавливаются Carbon, Oxide/uMod или другие плагины.

## 1. Основа — штатная функция Rust

В Rust есть встроенное право пропуска очереди. Facepunch описывает команду global.skipqueueid <SteamID64> [name] [note]; назначенные пользователи сохраняются в users.cfg. Для снятия права существует global.removeskipqueue <SteamID64>. Эти команды являются серверными командами Rust, а не функциями плагина.

Источники:
- Facepunch Wiki — Creating a hidden, whitelisted server: https://wiki.facepunch.com/rust/Creating_a_hidden_whitelisted_server
- Facepunch commit — Add skipqueueid and removeskipqueue commands: https://commits.facepunch.com/Rohan/rust_reboot/main/general_qol/skipqueue

## 2. Предлагаемый жизненный цикл пропуска

1. Игрок входит на сайт через подтверждённый Steam OpenID.
2. После будущего отдельного утверждения платёжной схемы backend получает подтверждение оплаты от провайдера. Возврат браузера на сайт не считается оплатой.
3. Backend связывает заказ с проверенным SteamID64 и записывает срок действия — 7 суток — в Firestore.
4. Серверный worker, имеющий доступ к RCON, выполняет команду:
   global.skipqueueid <SteamID64> "<nickname>" "Rusty.Lub VIP Queue Pass"
5. После изменения конфигурации worker выполняет server.writecfg, чтобы право сохранилось в users.cfg.
6. Cloud Scheduler запускает защищённую задачу проверки истёкших сроков. Для каждого истёкшего пропуска worker выполняет:
   global.removeskipqueue <SteamID64>
7. После снятия права worker выполняет server.writecfg и отмечает операцию завершённой в Firestore. Повторный запуск не должен повторно выдавать или продлевать пропуск.

## 3. Где выполняется автоматизация

Автоматизация находится вне игрового сервера:
- Cloud Run хранит записи о пропусках и выполняет серверные операции.
- Cloud Scheduler периодически вызывает закрытый endpoint или Cloud Run Job.
- Backend отправляет команды на RCON по защищённому каналу.
- RCON host, port и password хранятся только в Google Secret Manager / серверных переменных.
- Браузер не получает RCON-пароль и не отправляет игровые команды напрямую.

На Rust-сервере остаётся только штатный RustDedicated и его обычная конфигурация. Никакой плагин, модифицированный игровой UI или Carbon bridge не нужен.

## 4. Обязательные проверки до реализации

- Проверить на фактической версии RustDedicated через RCON, что обе команды доступны и имеют ожидаемую сигнатуру.
- Выдать тестовое право одному тестовому SteamID64, проверить вход в очередь, затем снять право и проверить повторное подключение.
- Проверить сохранение users.cfg после server.writecfg и после перезапуска сервера.
- Проверить истечение срока, повторные задания, сетевой сбой RCON и повторное выполнение задачи.
- Проверить поведение для забаненного игрока, владельца/модератора и игрока, у которого уже есть skip-queue право по другой причине.
- Не снимать чужое или вручную выданное право автоматически: нужен реестр происхождения права и заранее согласованная политика конфликтов.
- Убедиться, что при временной недоступности RCON система не помечает выдачу или снятие как выполненное.

## 5. Ограничения

- Это право даёт приоритет при подключении, а не повышенные рейты, предметы, ресурсы или игровые способности.
- Команда пропуска очереди не гарантирует свободный слот и не отменяет бан или ограничения Steam.
- Автоматическое снятие требует внешнего планировщика и безопасного RCON-доступа. Без этого остаётся только ручное управление командами администратора.
- Нельзя запускать продажу до проверки команд на реальном сервере, согласования условий/возвратов и отдельного подтверждения владельца проекта.

## 6. Решение

Рекомендуемый вариант: штатные Rust-команды + внешний Cloud Run worker + Cloud Scheduler + Firestore. Это сохраняет Vanilla-сервер без плагинов и не требует Carbon. Реализация не начинается до отдельного утверждения.
